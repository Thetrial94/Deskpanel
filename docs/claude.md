# Claude Code в DeskPanel

На компьютере с Node.js 22.13+ выполни из папки DeskPanel:

```sh
node scripts/install-claude-hooks.mjs
```

Установщик добавляет только обработчики DeskPanel в `~/.claude/settings.json` (или `%CLAUDE_CONFIG_DIR%/settings.json`). Остальные настройки и обработчики сохраняются, резервная копия лежит в `.runtime/backups`. Повторный запуск не создаёт дубликатов. После перемещения папки DeskPanel удали старые обработчики и установи заново. Уже открытые сессии Claude Code нужно перезапустить: обработчики читаются при старте.

## Что показывают события

- UserPromptSubmit / PreToolUse / PostToolUse: работа.
- PreToolUse с инструментом `AskUserQuestion` или уведомление `elicitation_dialog`: ждёт ответа.
- PermissionRequest или уведомление `permission_prompt`: ждёт разрешения.
- Stop: ответ завершён. Это не утверждение, что вся задача выполнена. У Claude Code нет отдельного события прерывания: прерванный ход тоже заканчивается как Stop.
- SessionStart: ожидает задачу; SessionEnd убирает сессию.
- Остальные уведомления (например, `idle_prompt`) игнорируются, чтобы не затирать статус завершённого ответа.
- Через 120 секунд без событий статус «Работает» становится «Нет свежих событий». Ожидание ответа и разрешения не приходит с новыми событиями, пока вы не ответили, поэтому оно держится до 30 минут.

Название карточки — имя папки проекта (`cwd`). Если нужны названия чатов, это отдельная доработка.

## Данные и доступ

Обработчик получает JSON от Claude Code, сразу оставляет только разрешённые поля и отвечает нейтральным `{}`: не принимает решений о разрешениях, не добавляет контекст, не блокирует. Не читает транскрипты, не сохраняет текст запросов и ответов, аргументы инструментов и полный путь. Идентификатор сессии хешируется SHA-256. Записи лежат в `%LOCALAPPDATA%/DeskPanel/claude`, по одной на сессию; сервер исключает записи старше суток и удаляет их при чтении.

Команда в settings.json использует прямые слэши, потому что Claude Code на Windows запускает обработчики через Git Bash.

Чтобы отключить: останови DeskPanel, удали `%LOCALAPPDATA%/DeskPanel/claude/installed.json` и удали из `settings.json` только записи, ссылающиеся на `claude-hook.mjs`.

Общий для двух провайдеров экран и контракт `GET /api/agents` описаны в [codex.md](codex.md) и [architecture.md](architecture.md).

## Пятичасовой и недельный лимиты

Сбор выполняется **на ПК с Claude Code** через официальные поля `statusLine`: `rate_limits.five_hour` и `rate_limits.seven_day`. Они содержат `used_percentage` и `resets_at` (Unix-секунды). Нужна версия Claude Code, которая передаёт эти поля. По документации они появляются после первого ответа модели у поддерживаемых подписок claude.ai; для API/провайдеров, которые их не передают, шкалы показывают «Нет данных». Контекстное окно и стоимость API не подменяют лимиты подписки.

После обновления Git повторно выполни на этом ПК:

```powershell
node scripts/install-claude-hooks.mjs
```

Установщик добавляет `scripts/claude-statusline.mjs`, сохраняет другие настройки и делает резервную копию. Если уже была пользовательская `statusLine`, DeskPanel продолжает запускать её с исходным JSON и сохраняет её вывод и параметры оформления. Предыдущая команда хранится только локально в `%LOCALAPPDATA%/DeskPanel/claude/previous-statusline.json`; повторная установка не создаёт цепочку из копий DeskPanel. Таймаут прежней команды — 4 секунды, при ошибке выводится встроенный краткий остаток лимитов.

Сборщик сохраняет **только** два процента, два времени сброса и время получения в `%LOCALAPPDATA%/DeskPanel/claude/usage.json`. Тексты, токены, идентификаторы аккаунта и пути из statusLine не записываются. Хаб пересылает `provider.usage` с того же ПК, что и Claude-сессии. Его выключение не отключает лимиты Codex с ноутбука.

Проверь после перезапуска Claude Code и первого ответа: `GET /api/agents/local` на ПК содержит `providers[id=claude].usage`. В общей панели выбранный источник Claude должен быть именно этот ПК. Устаревание и сброс обрабатываются так же, как у Codex; неизвестное значение не равно нулевому расходу.

Чтобы отключить сбор, восстанови прежнюю `statusLine` из локальной резервной копии (или удали поле, если раньше его не было). Не удаляй другие настройки.
