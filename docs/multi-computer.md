# Работа на двух компьютерах через Git

Общий репозиторий: https://github.com/Thetrial94/Deskpanel
Текущая рабочая ветка: `codex/initial-panel`.

Git переносит исходники и документацию. Сервер DeskPanel, подключения и статусы агентов остаются локальными на каждом компьютере.

## Первое получение на втором компьютере

Нужны Git и Node.js 22.13+. В выбранной папке:

```sh
git clone --branch codex/initial-panel https://github.com/Thetrial94/Deskpanel.git
cd Deskpanel
npm ci --ignore-scripts
npm test
npm run check
npm run start:phone
```

Открой адрес `Phone:` на телефоне. На втором компьютере создай новый код привязки через localhost:4317 и введи его на телефоне. Для одной общей панели настрой постоянный [хаб](hub.md): он привязывается к обоим компьютерам по кодам. Сохранённые кнопки переключают пульт, а Codex и Claude читаются одновременно. Оба сервера на компьютерах работают независимо.

## Получение обновлений

Перед обновлением останови свой сервер (Ctrl+C в окне запуска). Если установлен автозапуск, сначала выполни `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\deskpanel.ps1 -Action Stop`, иначе наблюдатель запустит сервер снова. После обновления возобнови наблюдатель командой `-Action Start`; обычный `npm run start:phone` оставлен для ручного запуска. [Подробнее об автозапуске](reliability.md). Проверь `git status`: сначала сохрани локальные правки коммитом, если они есть. Затем:

```sh
git switch codex/initial-panel
git pull --ff-only origin codex/initial-panel
npm ci --ignore-scripts
npm test
npm run check
npm run start:phone
```

После запуска обнови страницу на телефоне. Если pull сообщает о расхождении веток, согласуй и объедини изменения; не используй reset --hard или force push для устранения конфликта.

## Продолжение работы с Claude на другом компьютере

Claude здесь намеренно не установлен и не подключён. На компьютере с Claude сначала получи текущую ветку, затем реализуй адаптер `server/adapters/claude.mjs`. UI уже общий для двух провайдеров.

Контракт `GET /api/agents`: schemaVersion 1, providers с id `codex` / `claude`, connection и sessions. Сессия: стабильный хешированный id, пользовательское название title, status, updatedAt, startedAt и необязательное statusSince (ISO-время реального перехода статуса, не время опроса). Статусы: working, waiting, approval, completed, interrupted, idle, stale, error. Если время перехода неизвестно, statusSince=null; UI не выдумывает длительность.

Сначала проверь установленную версию и формат реальных событий Claude. Не считай наличие процесса доказательством работы. Не копируй настройки Codex hooks в Claude. Из событий сохраняй только название, хешированный ID, статус и время; тексты чатов и аргументы инструментов не нужны. Проверь живые переходы работа → вопрос → ответ → завершение, разрешение → решение, прерывание и устаревание. Общие тесты должны продолжать проходить.

Для последовательной работы можно коммитить и пушить в общую ветку после pull. Если изменения идут одновременно на обоих компьютерах, используй отдельную ветку (например `codex/claude-integration`) и объединение через PR. После публикации второй компьютер делает pull и перезапускает сервер.

Локальные `.runtime/`, node_modules, токены, приватные ссылки календаря, настройки hooks и привязки телефона не передаются через Git. При использовании постоянного хаба календарь и дом подключаются на хабе; хуки агентов и плеер устанавливаются на соответствующих компьютерах. Не добавляй их в коммиты.

Общие календарь и умный дом настраиваются на постоянно работающем мини-ПК. Подробная схема и установка — [хаб](hub.md). Старые ссылки на другие панели сами по себе не подключают агентов.
