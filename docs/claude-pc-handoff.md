# Обновить Claude на стационарном ПК: сессии и лимиты

Выполни на ПК с Claude в существующей папке DeskPanel. Реальные хуки и адаптер Claude уже реализованы, заглушки нет. Ноутбук с Codex не меняй.

1. Проверь `git status`. При локальных изменениях сохрани их отдельным коммитом и объедини с обновлением; не используй reset/clean и не затирай настройки.
2. Для чистой ветки `codex/initial-panel`:

```powershell
git pull --ff-only origin codex/initial-panel
npm install
node scripts/install-claude-hooks.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deskpanel.ps1 -Action Stop
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deskpanel.ps1 -Action Start
```

3. Установщик добавляет хуки статусов и сборщик лимитов через `statusLine`, сохраняет прежние настройки/строку состояния с резервной копией. Проверь установленную версию Claude Code: она должна передавать `rate_limits.five_hour` и `rate_limits.seven_day`. Не читай OAuth-файлы и не вызывай недокументированные endpoints с токенами. Не устанавливай хуки Claude на ноутбуке.
4. Перезапусти сессии Claude Code и дождись первого ответа. Проверь локально `/api/agents/local`: у Claude реальные сессии, а в `usage.windows` есть `fiveHour`/`week` с процентом расхода и временем сброса. В вывод проверки достаточно дать availability и два процента; названия чатов, настройки и секреты не печатай. Если поля не пришли, выясни версию/поддержку statusLine в используемом интерфейсе; не вычисляй расход по контексту. Живые данные Claude на ноутбуке не проверялись.
5. Проверь работу → вопрос → ответ → завершение и разрешение → решение. `Stop` означает конец ответа, а не выполнение всей задачи. Через 120 секунд без событий активный статус устаревает.
6. Существующую привязку к хабу сохрани. При первой привязке получи одноразовый код на localhost:4317, добавь ПК в настройках хаба на телефоне с ролью Claude. Код и IP не сохраняй в Git. Codex и Claude читаются независимо, музыка управляется на выбранном включённом компьютере.
7. Выполни `npm test` и `npm run check`. Код и документацию передавай через Git, пользовательские настройки/usage/события — только локально. Для параллельных правок используй отдельную ветку и обычное объединение без force push.
