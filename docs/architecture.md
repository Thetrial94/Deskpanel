# Архитектура и границы первой версии

## Экран как модуль

Каждый экран экспортирует объект:

```js
export default {
  id: 'example',
  title: 'Название',
  icon: 'clock',
  accent: 'lime',
  mount(root, context) {
    // Создать содержимое внутри root.
    // context: settings(), weather, agents, focus, music, breaks, computer, remote, calendar, home.
    return () => {
      // Отписаться от источников и остановить свои таймеры.
    };
  }
};
```

Экран регистрируется в `src/screens/registry.js`, а его ID добавляется в `SCREEN_IDS` в `src/core/settings.js`. Экран не управляет навигацией. При смене вызывается cleanup предыдущего модуля; в DOM находится один активный экран.

Это модульная архитектура исходников, а не установка сторонних плагинов из ZIP. UI установки стороннего кода в первой версии отсутствует.

## Смена экранов

`RotationClock` использует монотонное время браузера. После ручного перехода работает задержка `resumeAfter`, затем полный интервал показа. При открытых настройках или подтверждении действия, скрытой вкладке, ручной паузе или единственном экране переключения нет. После возврата из фонового режима не происходит ускоренной смены пропущенных экранов.

Горизонтальный свайп должен пройти минимум 48 CSS-пикселей и превышать вертикальное смещение в 1,3 раза. Жесты на кнопках/полях не захватываются. Вертикальная прокрутка остается доступной.

## Источники данных

- Часы: локальное время устройства.
- Фокус: абсолютный deadline и сохранение в localStorage.
- Погода: Open-Meteo, по умолчанию Москва; обновление не чаще раза в 10 минут. При ошибке предыдущие данные сохраняются с отметкой о потере связи.
- Агенты: чтение `GET /api/agents` раз в 15 секунд. В первой версии оба адаптера всегда возвращают `not_configured`.

## Контракт агентов

```json
{
  "schemaVersion": 1,
  "providers": [
    {
      "id": "codex",
      "name": "Codex",
      "connection": "not_configured",
      "sessions": [],
      "updatedAt": null
    }
  ]
}
```

Провайдеры: `codex`, `claude`.
Состояние соединения: `not_configured`, `connected`, `disconnected`.
Планируемое состояние сессии: `working`, `waiting`, `completed`, `error`, `idle`.
Поля сессии: `id`, `title`, `status`. Неизвестное состояние отображается как неизвестное.

До подключения реальных агентов дополнить контракт freshness/heartbeat, протестировать stale-сценарий и защитить доступ к локальному bridge. Текущий сервер не читает никаких данных агента и не дает удаленного управления агентами.

## Локальный сервер

Node.js 22+, node-ical для разбора ICS. По умолчанию слушает 127.0.0.1; `--lan` явно включает доступ по локальной сети. Отдает только index.html, src/ и public/. Серверные исходники, .git, README и прочие файлы не доступны по HTTP. Поддерживаются GET и HEAD; POST разрешён для ограниченных команд music, remote, home, а также access и connections. Подробности — в [описании музыкального моста](music.md).

Нет облачной публикации, автоматического запуска вместе с Windows, service worker и автономной работы без компьютера. Для новых приватных API реализована привязка телефона; музыкальное API сохраняет прежнюю модель доверенной домашней сети.

## Подключения и приватные API

`Features` объединяет `/api/access`, `/api/connections`, `/api/computer`, `/api/remote`, `/api/calendar`, `/api/home`. Проверяются Host и Origin; изменяющие запросы требуют same-origin, JSON и `X-DeskPanel: 1`. Это защита от вызовов другой веб-страницей, не замена сетевой изоляции.

На loopback разрешена локальная настройка. Телефон получает случайный HttpOnly / SameSite=Strict cookie на 30 дней после ввода шестизначного одноразового кода (3 минуты, до 5 ошибочных попыток с IP за 10 минут). В серверном хранилище только хеш cookie; конфигурация зашифрована DPAPI CurrentUser. Секреты не возвращаются клиенту. Локальная настройка доступна только через loopback Host и loopback-соединение. Удалённое изменение подключений запрещено даже привязанному телефону.

Календарь загружается сервером по HTTPS без перенаправлений, ограничен 1 МБ. Разбор выполняется в worker с ограничением памяти и времени; диагностика библиотеки не попадает в журнал сервера. На клиент уходят только название, начало, конец, признак целого дня и ID. Горизонт — 7 дней, до 30 событий, кеш 5 минут. Учитываются EXDATE, переносы и отмены повторений. Время отображения — Москва.

`Home` использует фиксированный API Яндекса или явно указанный Home Assistant. Управлять можно светом, розетками и выключателями; датчики HA доступны для чтения. Запросы ограничены по времени/объёму; перед командой заново проверяются возможности устройства, для Яндекса проверяется результат выполнения. Замки и другие типы не получают кнопок управления. Подтверждение действия находится в интерфейсе панели.

`Computer` собирает показатели через Node os, команды Windows исполняет отдельный скрытый процесс PowerShell с фиксированным списком действий. Произвольной консоли нет. Микрофон — устройство связи по умолчанию; аудиовыход — устройство мультимедиа по умолчанию. Выбор аудиоустройства пока открывает настройки Windows на ПК.

Источники новых экранов опрашивают API только пока экран смонтирован и вкладка видима. Таймер перерывов использует абсолютный deadline; завершённый рабочий интервал ждёт явного начала отдыха. В фоновой/закрытой вкладке браузер может задержать напоминание; системных уведомлений нет.

Ссылки на компьютеры переключают всю панель на другой сервер. Это не центральный сборщик статусов и не перенос музыки. При смене сервера настройки браузера и привязка отдельные.
