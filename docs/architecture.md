# Архитектура и границы первой версии

## Экран как модуль

Каждый экран экспортирует объект:

```js
export default {
  id: 'example',
  title: 'Название',
  icon: 'clock',
  accent: 'lime',
  mount(root, context) {
    // Создать содержимое внутри root.
    // context: settings(), weather, agents, focus.
    return () => {
      // Отписаться от источников и остановить свои таймеры.
    };
  }
};
```

Экран регистрируется в `src/screens/registry.js`, а его ID добавляется в `SCREEN_IDS` в `src/core/settings.js`. Экран не управляет навигацией. При смене вызывается cleanup предыдущего модуля; в DOM находится один активный экран.

Это модульная архитектура исходников, а не установка сторонних плагинов из ZIP. UI установки стороннего кода в первой версии отсутствует.

## Смена экранов

`RotationClock` использует монотонное время браузера. После ручного перехода работает задержка `resumeAfter`, затем полный интервал показа. При открытых настройках, скрытой вкладке, ручной паузе или единственном экране переключения нет. После возврата из фонового режима не происходит ускоренной смены пропущенных экранов.

Горизонтальный свайп должен пройти минимум 48 CSS-пикселей и превышать вертикальное смещение в 1,3 раза. Жесты на кнопках/полях не захватываются. Вертикальная прокрутка остается доступной.

## Источники данных

- Часы: локальное время устройства.
- Фокус: абсолютный deadline и сохранение в localStorage.
- Погода: Open-Meteo, только после явного выбора города; обновление не чаще раза в 10 минут. При ошибке предыдущие данные сохраняются с отметкой о потере связи.
- Агенты: чтение `GET /api/agents` раз в 15 секунд. В первой версии оба адаптера всегда возвращают `not_configured`.

## Контракт агентов

```json
{
  "schemaVersion": 1,
  "providers": [
    {
      "id": "codex",
      "name": "Codex",
      "connection": "not_configured",
      "sessions": [],
      "updatedAt": null
    }
  ]
}
```

Провайдеры: `codex`, `claude`.
Состояние соединения: `not_configured`, `connected`, `disconnected`.
Планируемое состояние сессии: `working`, `waiting`, `completed`, `error`, `idle`.
Поля сессии: `id`, `title`, `status`. Неизвестное состояние отображается как неизвестное.

До подключения реальных агентов дополнить контракт freshness/heartbeat, протестировать stale-сценарий и защитить доступ к локальному bridge. Текущий сервер не читает никаких данных агента и не дает удаленного управления.

## Локальный сервер

Node.js без пакетов. По умолчанию слушает 127.0.0.1; `--lan` явно включает доступ по локальной сети. Отдает только index.html, src/ и public/. Серверные исходники, .git, README и прочие файлы не доступны по HTTP. Поддерживаются только GET и HEAD.

В первой версии нет облачной публикации, авторизации, автоматического запуска вместе с Windows, service worker и обещания автономной работы без компьютера.
