# Codex в DeskPanel

На компьютере с Node.js 22.13+ выполни из папки DeskPanel:

```sh
node scripts/install-codex-hooks.mjs
```

Установщик добавляет только обработчики DeskPanel в пользовательский hooks.json. Остальные обработчики сохраняются, резервная копия находится в `.runtime/backups`. Повторная установка той же команды не создаёт дубликатов. После перемещения папки удали старые обработчики DeskPanel и установи новые.

В Codex открой Settings → Hooks, проверь и разреши обработчики «DeskPanel: статус агента». Если активный чат не подхватил изменение, перезапусти Codex и отправь обычное сообщение. Пока первое реальное событие не получено, панель показывает «Ждём первое событие». Установщик не изменяет хранилище доверия.

## Резервное чтение статусов приложения

Если поток hooks не поступает, после установки моста DeskPanel также читает **только служебные метаданные** локального Codex. Поддерживается структура `state_5.sqlite` и `thread_history_1.sqlite` в CODEX_HOME (по умолчанию ~/.codex). Обе базы открываются read-only; запросы выбирают только ID, пользовательское название чата (`name`), время обновления и статус последнего корневого хода. Preview, аргументы инструментов и транскрипты не читаются. Для ожидания ответа дополнительно используется описанная ниже корреляция служебных событий.

На экран попадают последние сессии за сутки, без архивных, максимум 12; идентификаторы хешируются. Карточки показывают название чата из Codex; если оно отсутствует — «Сессия» и короткий идентификатор. Активная запись без обновлений более 120 секунд помечается как устаревшая. Свежие события hooks имеют приоритет для той же сессии, кроме подтверждённого ожидания ответа. Без установочного маркера мост не читает базы Codex.

Этот источник различает «В процессе», «Ждёт ответа», «Ответ завершён», «Прервано» и «Ошибка». Ожидание разрешения пока определяется только через hooks.

Для «Ждёт ответа» адаптер также открывает `logs_2.sqlite` только на чтение. Из технических записей завершения `request_user_input_async` извлекаются ID вызова и хода; из служебных сообщений `<send_user_message_question_reply>` SQL возвращает только `questionItemId`. Текст вопроса и ответа не возвращается из запроса, не сохраняется DeskPanel и не передаётся на телефон. Обычные сообщения не используются для определения ответа.

Ожидание сохраняется после завершения сообщения агента и снимается после служебного ответа с тем же ID вызова либо прерывания/ошибки соответствующего хода. Отправка формы ответа считается ответом на вызов целиком; отдельное состояние частично заполненной формы не отслеживается. Период поиска — сутки, максимум 64 последних вызова на чат. По истечении суток ожидание больше не показывается. При отсутствии или несовместимой схеме журналов остаются основные статусы. На остальных экранах появляется жёлтая плашка; нажатие открывает Codex. Это уведомление внутри открытой панели, а не системное push-уведомление. Формат базы внутренний и может измениться после обновления Codex; при несовместимой структуре адаптер перестаёт читать её и сохраняет маршрут hooks. Нужен Node.js с модулем node:sqlite (22.13+).

## Что показывают события hooks

- UserPromptSubmit / PreToolUse / PostToolUse: работа.
- PermissionRequest: запрошено разрешение; автоматическое одобрение может быстро сменить статус.
- Вызов инструмента запроса ответа: запрошен ответ.
- Stop: ответ завершён. Это не утверждение, что вся задача выполнена.
- Interrupt: прервано.
- SessionStart: ожидает задачу; SessionEnd убирает сессию.
- Через 120 секунд без событий активный статус становится «Нет свежих событий». Долгое размышление без инструментов также может попасть в это состояние.

Сверху показываются сессии, требующие внимания. Название берётся из поля `name` чата Codex и обновляется после переименования. Свежие hooks уточняют статус, сохраняя название чата. Панель обновляет данные каждые 3 секунды в видимой вкладке.

## Данные и доступ

Hook получает стандартный JSON Codex, сразу оставляет только разрешённые поля и выводит нейтральный `{}`. Не читает транскрипты, не сохраняет текст запроса, ответа, аргументы инструментов или полный путь. Идентификаторы сессии и хода хешируются SHA-256. Записи лежат в `%LOCALAPPDATA%/DeskPanel/codex`, по одной на сессию. Сервер исключает записи старше суток и удаляет свои устаревшие файлы при чтении. Зависшая файловая блокировка восстанавливается после 10 секунд.

На телефоне нужна привязка по коду. Экран показывает события только этого компьютера; не отправляет команды агенту. Для другого компьютера установи сервер и мост там и добавь адрес его панели.

Чтобы полностью отключить мост, останови DeskPanel, удали только `%LOCALAPPDATA%/DeskPanel/codex/installed.json` (он включает чтение метаданных), затем удали или отключи в Settings → Hooks только обработчики с подписью DeskPanel. Не заменяй весь hooks.json старой резервной копией, если после установки менялись другие хуки.

Документация событий: https://learn.chatgpt.com/docs/hooks
