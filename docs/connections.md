# Телефон, календарь и умный дом

## Привязка телефона

1. Запусти DeskPanel на Windows (`Start-Phone.cmd` или `npm run start:phone`). Нужен Node.js 22+; CMD-файл установит зависимости при первом запуске.
2. На этом же компьютере открой http://localhost:4317 → Настройки → Доступ с телефона → Показать код подключения.
3. На телефоне открой адрес `Phone:` из сервера → Настройки → введи код. Код действует 3 минуты, однократно; после пяти неверных попыток нужна пауза 10 минут.
4. Привязка действует 30 дней в этом браузере. После очистки cookie подключи телефон снова. Код не нужно присылать в чат.

Через LAN-адрес локальная настройка недоступна, даже если открыть его на самом компьютере. Для настройки используй именно localhost. Общий пульт музыки работает по прежней схеме домашней сети.

Сервер работает по HTTP в доверенной домашней сети; cookie, календарные события и команды не защищены шифрованием на пути. Не открывай этот порт в интернет. Установка HTTPS/центрального хаба — отдельный этап.

## Рабочий Яндекс Календарь / Yandex Team

В настройках нужного календаря найди экспорт / подписку **iCal (ICS)**. Вставь приватную ссылку в поле календаря в DeskPanel на localhost. Не вставляй её в Git или чат. Принимаются HTTPS-ссылки calendar.yandex.ru, calendar.yandex.com, calendar.yandex-team.ru и cal.yandex-team.ru.

Обычный адрес страницы календаря не подходит. Если организация запрещает экспорт или ссылка требует браузерной авторизации, этот адаптер не подключится: понадобится отдельная разрешённая интеграция. Текущая версия не использует корпоративные cookie или пароли.

Экран показывает ближайшие семь дней по московскому времени, обновление не чаще раза в пять минут. При ошибке виден статус потери связи, а не пустой «успешный» календарь. Отмена встречи в источнике отразится после обновления кеша.

## Яндекс / Алиса

Нужен OAuth-токен для аккаунта с устройствами и разрешениями **iot:view** и **iot:control**. Токен создаётся через своё OAuth-приложение Яндекса с согласия владельца; встроенной регистрации OAuth-приложения в DeskPanel пока нет.

В настройках DeskPanel на localhost выбери «Яндекс / Алиса», вставь токен и сохрани. Он остаётся на компьютере. Поддержаны просмотр устройств и включение/выключение света, розеток, выключателей. На каждое действие есть подтверждение. Термостаты, замки, сценарии и голосовые команды пока не реализованы.

Первичные источники:

- https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-protocol
- https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-user-info
- https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-capabilities

## Будущий Home Assistant

Если появится свой хаб, выбери Home Assistant, укажи его адрес (например, `http://homeassistant.local:8123`) и долгосрочный токен из профиля HA. HTTP допускается только для локальных адресов, для внешнего адреса нужен HTTPS. Поддержаны сущности light, switch и sensor; датчики только для чтения. Аппаратный хаб эта настройка не устанавливает.

Документация API: https://contributors.home-assistant.io/core/internals/rest-api/

## Хранение

Конфигурация и хеши привязанных устройств находятся в `%LOCALAPPDATA%\DeskPanel\connections.bin`, зашифрованном Windows DPAPI CurrentUser. Перенос этого файла на другой компьютер/пользователя не переносит подключение. Поля секретов после сохранения очищаются и обратно не заполняются. Для удаления конкретной интеграции есть кнопка «Отключить».

## Ноутбук и стационарный компьютер

На каждом компьютере нужно запустить свой DeskPanel и расширенную Яндекс Музыку RS, если требуется музыкальный пульт. Добавь название и LAN-адрес второй панели в настройках телефона. Экран «Компьютеры» откроет выбранную панель: музыка и пульт будут управлять именно её компьютером. Привяжи телефон к каждому серверу отдельно.

Текущая панель не измеряет доступность остальных компьютеров; сохранённые пункты — ссылки. Пока ноутбук выключен, размещённая на нём панель недоступна. Постоянный независимый сервер и общая панель всех устройств ещё не реализованы.

## Проверено и ожидает подключения

Проверены реальные показатели ноутбука, чтение состояния Windows CoreAudio и изменение громкости 12 → 13 → 12, отмена блокировки в интерфейсе, перерывы, защищённое хранилище DPAPI. Сама блокировка намеренно не выполнялась. Микрофон и открытие настроек аудиовыхода требуют пользовательской проверки.

Календарные правила и протоколы умного дома проверены на тестовых данных. Рабочая ICS-ссылка, токен умного дома и адрес второго ПК ещё не предоставлены, поэтому живое подключение этих сервисов не проверено.
